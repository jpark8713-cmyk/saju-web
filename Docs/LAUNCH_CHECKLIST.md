## 3. 지금 알고 있는 남은 위험 (결정 대기 아님)

참고용이에요. 위 항목이 끝나도 남아요.

- **메일 중복 발송 가능성:** 메일 재시도 대기 중 서버가 멈추면 다시 켤 때 처음부터 보내요. 이미 1통이 나갔으면 2통이 될 수 있어요(D-033).
- **"보냄" 기록 실패 시 재발송:** 메일을 보낸 뒤 "보냄" 기록이 4번 연속 실패하면, 다음 서버 시작 때 한 통이 더 나갈 수 있어요(D-035).
- **PDF는 백업에 없음:** PDF 파일은 Object Storage 백업에 들어가지 않아요. 복원한 뒤에는 고객이 처음 받을 때 리포트로 다시 만들어요(D-033).
- **예전 기록의 결제 경고 누락:** "승인 여부 모름" 전용 칸이 생기기 전의 주문 중 만료 거절로 마지막 오류가 `ORDER_EXPIRED_AFTER_PG_UNREACHABLE`로 바뀐 주문은 SQLite 경고 조회에서 빠져요. 출시 전 주문에는 해당이 없어요(D-054 리뷰, 낮은 위험).
- **실제 PG 어댑터의 연결 오류 처리:** 2-8의 확인 항목이에요. 어댑터가 연결 오류를 실패 값으로 돌려주면 "승인 여부 모름" 칸에 기록되지 않을 수 있어요(D-054 리뷰).
- **승인 도중 서버가 멈춘 결제:** "승인 여부 모름" 칸에 들어가지 않아요. 출생 정보 정리에서는 빠지고 2-9 복구 명령으로 처리해요(D-054 리뷰, 낮은 위험).
- **생성 중에 멈춘 주문의 출생 정보:** 정리 작업은 "생성 중" 주문을 건너뛰어요. 멈춘 생성은 주문 조회·서버 시작 때 실패로 바뀐 뒤 다음 정리에서 지워져요(D-054 리뷰, 낮은 위험).
- **관리 명령 `payments resolve`의 `--key` 값 빠뜨림:** `--key`를 마지막에 쓰고 값을 빼먹으면 키를 지정하지 않은 것으로 보고 그 주문의 승인 여부 모름 키를 모두 끝내요. 실행 전 `payments uncertain`으로 키를 확인하고 값을 꼭 적어요(D-054 리뷰, 낮은 위험).
- **예전 기록의 목록 누락:** 목록·경고 조회는 예전 기록 중 `PG_UNREACHABLE`만 보고, 만료 거절로 `ORDER_EXPIRED_AFTER_PG_UNREACHABLE`이 된 예전 주문은 빠져요. 출시 전 주문에는 해당이 없어요(D-054 리뷰, 낮은 위험).
- **오래된 잠금 뒤 취소 실패:** 금액 불일치 취소가 실패했는데 그사이 결제 키가 바뀐 드문 경우에는 승인 여부 모름 칸에 기록되지 않아요. 정상 흐름에서는 승인 중에 결제 키가 바뀌지 않아요(D-054 리뷰, 낮은 위험).
- **`approved-kept` 기록의 한계:** 결과를 기록하면 경고만 끝나고 주문은 결제 완료로 바뀌지 않아요(2-9 복구 명령 전에는 수동 처리). 메모(`--note`)에는 길이 제한이 없으니 개인정보를 적지 않아요(D-054 리뷰, 낮은 위험).
- **절입 시각의 공식 대조 범위:** 천문연 24절기 시각과 대조한 것은 2000~2028년(API가 응답하는 범위)뿐이에요. 348건 중 347건이 1분 안에서 맞았고 1건(2011 입동)은 천문연 API 데이터 오류로 판정했어요(D-012). 1900~1999년과 2029~2050년은 같은 계산식(lunar-javascript)에 기대고 있고, 공식 자료로 증명하지 않았어요. 독립 저정밀 검산(±15분)만 있어요.
- **음양력 변환의 공식 대조 없음:** 음력 변환은 천문연 자료 기반 라이브러리(manseryeok)를 써요. 출처가 다른 천문연 자료 기반 라이브러리(korean-lunar-calendar)와는 7,030개 날짜가 모두 같았어요(`Docs/MANSERYEOK_LIBCOMPARE.md`). 하지만 천문연 음양력 API와 직접 대조하지는 못했어요. 지금 키로는 음양력 서비스가 등록돼 있지 않아요(data.go.kr "한국천문연구원_음양력 정보" 활용 신청 필요).
- **표준시·서머타임은 런타임 tzdb에 기대요:** 연혁 표를 코드에 두지 않고 런타임의 IANA tzdb(`Asia/Seoul`)를 써요(1954-03-21 전환 시각만 원문대로 덧씌움). tzdb 2019c보다 오래된 런타임이면 1948~1951년 서머타임이 빠지는데, 전환표 테스트(`tests/engine/timezoneHistory.test.ts`)가 잡아요. 1950-09-10 하루는 한 시간 불확실해요(1-15).

  - **예행 모드의 "생성 실패" 선택지:** 목 결제창에서 "결제 성공 후 풀이 생성 실패"를 골라도 운영 빌드에서는 강제 실패가 꺼져 있어 실제 Claude API를 불러요(비용 발생, 실패 화면 재현 안 됨). 예행 연습에서는 이 선택지를 쓰지 않아요.
