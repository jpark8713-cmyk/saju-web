# 만세력 오픈소스 라이브러리 자동 비교

앱 수작업 비교(`MANSERYEOK_CHECK.md`) 대신 오픈소스 만세력 라이브러리 두 개와 우리 엔진을 기계로 비교한 결과예요. 입력은 모두 가상 값이고, 유료 호출은 없어요. 기준 커밋 `8c1cf49`, 실행일 2026-10-29.

## 결론

- **설정을 맞추면 전부 같아요.** 점검표 30건, 무작위 7,000건(절입 ±1일 1,966건 포함) 모두 두 라이브러리와 네 기둥이 일치했어요. 불일치 0건.
- **라이브러리 기본 설정 그대로 넣으면 34~39%가 달라요.** 차이는 전부 설정 차이로 설명돼요. 대부분 경도 보정 때문에 시주가 갈리고, 그다음은 라이브러리가 입력 시각을 베이징 시간(UTC+8)으로 받아 절입 전후를 1시간 어긋나게 보는 경우예요.
- **절입 시각:** 1900~2050년 1,812개 절입이 sxtwl과 최대 54초 차이예요(1900~1999년은 0.5초 이하). 공식 자료(KASI, 2000~2028)에는 우리 쪽이 더 가까워요(최대 37초, sxtwl은 50초).
- **음력 변환:** 한국천문연구원 자료 기반 `korean-lunar-calendar`와 7,030개 날짜 모두 같았어요.
- **확인하지 못한 것:** 서머타임·UTC+8:30 해석과 경도 보정 값 자체예요. 두 라이브러리 모두 이 기능이 없어서, 설정 맞춤 비교에서는 우리가 계산한 시각을 그대로 넣었어요. 이 부분은 점검표 13~17번과 `LAUNCH_CHECKLIST` 1-10(경도표 공식 대조)이 계속 맡아요.

## 비교 방법

라이브러리마다 두 번 계산했어요.

| 방식 | 년·월주 | 일주·시주 | 음력 입력 |
| --- | --- | --- | --- |
| 기본 설정 | 입력한 시계 시각을 그대로(라이브러리는 베이징 시간으로 받아들여요) | 입력한 시계 시각 그대로(경도 보정·서머타임 없음) | 라이브러리의 중국 음력으로 양력 변환 |
| 설정 맞춤 | 태어난 순간을 베이징 시간으로 바꿔 넣음(= 우리처럼 절입을 실제 순간으로 판정) | 우리가 구한 경도 보정 시각(서머타임·UTC+8:30 반영)을 넣음 | 우리 양력 변환 날짜 |

판정은 셋 중 하나예요.

- **같음:** 기본 설정에서도 같아요.
- **설정 차이로 설명됨:** 기본 설정에서는 다르고, 설정을 맞추면 같아요.
- **다름:** 설정을 맞춰도 달라요(이번에는 0건).

설정 맞춤 비교가 확인하는 것은 절입 전후 판정 규칙, 60갑자 일진, 시주 천간 규칙, 야자시 처리, 음력 변환이에요. 시각 해석(서머타임·과거 표준시·경도 보정)은 우리 값을 넣었으니 이 비교로는 확인되지 않아요.

시간을 모르면(7·28번) 우리 기본값처럼 12:00으로 세 기둥만, 분 모름(20번)은 08:00으로 세 기둥만 비교했어요. 대운은 라이브러리마다 대운수 계산법이 달라서 비교하지 않았어요.

## 기간 비교(1900~2050 무작위)

- **일반 표본 5,000건:** 1900-01-01~2050-12-31에서 날짜를 고르게 뽑았어요. 시각은 0~23시를 무작위로 고르고 30%는 정각, 나머지는 분까지 뽑았어요. 출생지는 서울·부산·강릉·광주·제주·대전·대구 중에서, 성별은 무작위로 골랐어요.
- **절입 집중 표본 2,000건:** 무작위 절입의 앞뒤 하루 안 날짜를 골랐어요.
- **시드 고정:** 20261029라서 다시 돌려도 같은 결과가 나와요.
- **"절입 ±1일":** 태어난 순간이 가장 가까운 절입에서 24시간 안인 경우예요. 일반 표본에서 326건, 집중 표본에서 1,640건으로 모두 1,966건이에요.

이 차이 때문에 두 계산의 결과가 갈리려면, 2000년 이후에 절입 1분 안쪽(최대 54초 폭)에서 태어나야 해요. 1년에 12번 × 54초이니, 무작위 출생 10만 명 중 2명 정도가 상한이에요.

## 한계와 남은 일

- 두 라이브러리는 같은 천문 알고리즘 계열이에요. 1900~1999년 절입의 정확도는 공식 자료와 직접 대조하지 못했어요(KASI 자료는 2000~2028만 받아 둠, `LAUNCH_CHECKLIST` 3장).
- 서머타임·UTC+8:30 해석(IANA tzdb)과 지역 경도 값은 이 비교로 확인되지 않아요. 점검표 13~17번과 `LAUNCH_CHECKLIST` 1-10이 남아 있어요.
- 대운(방향·대운수)은 비교하지 않았어요.
- 앱 수작업 비교(`MANSERYEOK_CHECK.md`)는 남겨 뒀어요. 시중 앱이 어떤 설정을 기본으로 쓰는지는 이 자동 비교로 알 수 없어요.

## 다시 돌리는 법

```bash
# 1) 우리 엔진 + lunar-javascript (출력 폴더는 저장소 밖 아무 곳)
npx tsx scripts/manseryeok-libcmp/generate.mts <출력 폴더>
npx tsx scripts/manseryeok-libcmp/jie-dump.mts <출력 폴더>/jie-ours.json
# 2) 파이썬 3.11 가상환경에 sxtwl·korean-lunar-calendar (sxtwl은 3.14용 휠이 없어요)
python -m pip install -r scripts/manseryeok-libcmp/requirements.txt
python -I scripts/manseryeok-libcmp/compare.py <출력 폴더>
python -I scripts/manseryeok-libcmp/jie_compare.py <출력 폴더>/jie-ours.json
python -I scripts/manseryeok-libcmp/kasi_compare.py tests/fixtures/kasi-jie.json <출력 폴더>/jie-ours.json
```

`compare.py`는 `<출력 폴더>/libcmp-result.json`에 사례별 결과와 통계를 남겨요.
